WS_ConversionUnidades_Java_GR8

Servicio REST de conversión de unidades (longitud, masa y temperatura) — TI.1.3, arquitectura SOAP/RESTful Java sin base de datos.

URL base

http://<host>:8080/WS_ConversionUnidades_Java_GR8/api

Ejemplo de sonda pública: GET /api/estado.

Endpoints

Método y ruta Token Cuerpo de entrada resultado (200)
GET /api/estado no — {servicio, version, protocolo, horaServidor}
POST /api/auth/login no {"username","password"} {token, usuario, expiraEn}
POST /api/auth/logout sí — true
GET /api/catalogo sí — {LONGITUD:[…], MASA:[…], TEMPERATURA:[…]}
POST /api/conversiones/{longitud|masa|temperatura} sí {"valorOrigen","unidadOrigen","unidadDestino"} {valorOrigen, valorResultado, unidadOrigen, unidadDestino, tipoMagnitud}

Envelope de respuesta

Éxitos y errores comparten siempre la misma forma, con las cuatro claves presentes:

{ "estado": "OK|ERROR", "codigo": 200, "mensaje": "texto", "resultado": { } }

En los errores resultado es null y codigo repite el código HTTP. Códigos usados: 400 datos inválidos, 401 sesión, 404 ruta o magnitud desconocida, 405 método incorrecto, 415 cuerpo que no es JSON y 500 error inesperado.

Autenticación

POST /api/auth/login devuelve un token de sesión vigente 30 minutos. Envíelo en las peticiones protegidas en el encabezado: 

Authorization: Bearer <token>

El esquema Bearer no distingue mayúsculas; sin encabezado o con un token desconocido o vencido la respuesta es 401 con el mensaje de acceso denegado.

Credenciales de prueba: usuario MONSTER, contraseña MONSTER9. Son credenciales en memoria (proyecto SINBDD): no modifique el servicio para cambiarlas.

Las peticiones POST deben declarar Content-Type: application/json.

Ejemplo

curl -X POST http://localhost:8080/WS_ConversionUnidades_Java_GR8/api/conversiones/longitud \
     -H "Content-Type: application/json" \
     -H "Authorization: Bearer <token>" \
     -d '{"valorOrigen":100,"unidadOrigen":"CENTIMETRO","unidadDestino":"METRO"}'
